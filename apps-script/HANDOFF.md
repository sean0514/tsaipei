# 境外實習生管理系統 — 專案交接文件

## 給 Claude Code 的一句話摘要

這是一個用 **Google Apps Script（後端）+ 單一 HTML 檔（前端 SPA）** 寫成的內部管理系統，
資料庫是 **Google 試算表**。沒有 build 工具、沒有套件管理、沒有本地開發伺服器 ——
所有程式碼直接貼進 Apps Script 線上編輯器執行。修改後必須手動部署新版本才會生效
（詳見「部署方式」）。這份文件是唯一的架構說明來源，程式碼本身沒有額外的設計文件。

---

## 1. 專案是什麼

「鈞羽有限公司」用來管理境外（越南/印尼/泰國/菲律賓）學生來台實習的內部後台系統。
涵蓋從學生建檔、職缺媒合、簽證/居留、實習文件、在台生活（住宿/關懷）、
到財務結算（獎金/請款）的完整流程。使用者透過帳號密碼登入（不是 Google 帳號登入），
依角色看到不同的功能與資料。

## 2. 技術架構

- **後端**：`Code.gs`（Google Apps Script，V8 執行環境，語法接近 ES6 但仍用 `var`/`function` 為主）
- **前端**：`Index.html`（單一檔案，內嵌 `<style>` 與 `<script>`，純原生 JS，無框架，
  透過 Apps Script 的 HTML Service 當作網頁應用程式提供服務）
- **資料庫**：Google 試算表，每個資料表對應一個分頁（sheet tab），第一次執行時
  `getSheet_()` 會自動建立分頁與表頭
- **前後端溝通**：前端用 `google.script.run` 包裝出的 `gsRun(fnName, ...args)` 呼叫
  `Code.gs` 裡的函式，函式簽章第一個參數幾乎都是 `token`（session token）
- **無任何 npm / build step**：`Index.html` 裡的 `<script>` 就是最終會在瀏覽器執行的程式碼

## 3. 部署方式

### 3a. 自動部署（已設定，push 到 main 就會觸發）

`.github/workflows/deploy.yml` 會在 push 到 `main` 分支時，用 `clasp push` 把
`apps-script/` 底下的檔案推到 Apps Script 專案，再用 `clasp deploy -i <deploymentId>`
更新既有的網頁應用程式部署（同一個網址，不會變）。

需要在 repo 的 Settings > Secrets and variables > Actions 設定三個 Secrets：
`CLASPRC_JSON`（clasp login 產生的憑證）、`CLASP_SCRIPT_ID`、`CLASP_DEPLOYMENT_ID`，
且 `apps-script/appsscript.json`（manifest）必須存在於 repo 裡（用 `clasp pull` 從線上
專案抓下來提交，避免 CI push 時用預設值覆蓋掉正式環境的執行身份/存取權限設定）——
這兩項目前還沒做，見部署指南或跟 Claude Code 要設定步驟。

### 3b. 人工操作（備用/CI 尚未設定完成前）

1. 打開對應的 Google 試算表 → 擴充功能 → Apps Script
2. 把 `Code.gs`、`Index.html` 整份內容覆蓋貼上（覆蓋，不是新增）
3. 存檔
4. 右上角「部署」→「管理部署作業」→ 編輯現有部署（不要新增部署，網址會變）→
   版本選「新版本」→ 部署
5. 第一次執行、或新增了需要新權限的功能（例如 `SpreadsheetApp.create`、`DriveApp`、
   `UrlFetchApp`）時，使用者可能會被要求重新授權

Claude Code 在這個沙盒環境裡沒有瀏覽器，無法自己完成 `clasp login` 的 OAuth 授權，
所以 CI 憑證（`CLASPRC_JSON`）需要人工在本機產生後貼進 GitHub Secrets。

## 4. 檔案結構

```
apps-script/
  Code.gs          後端：資料表結構、CRUD、權限、同步邏輯、Excel 請款單產生
  Index.html       前端：整個 SPA（HTML + CSS + JS 都在這一個檔案裡）
  部署指南.md       給非工程背景的使用者看的部署步驟（中文，圖文步驟）
  HANDOFF.md       本檔案
```

**兩個檔案都很大**（Code.gs 約 1,100 行、Index.html 約 4,300+ 行），修改時建議：
- 先用 grep/搜尋定位相關函式，不要整份讀完再改
- `Index.html` 裡同一個「頁面」的 render 函式、表單 modal、事件綁定分散在檔案三個
  不同區塊（render 函式群、modal 函式群在中段，`attachPageEvents()` 裡的事件綁定
  在檔案後段），修改一個頁面通常要同時改三個地方

## 5. 資料表總覽（Google 試算表分頁）

定義在 `Code.gs` 的 `SHEET_FIELDS` 物件裡，每個表都是 `[{key, label}, ...]` 的陣列，
`key` 是程式裡用的欄位名，`label` 是試算表欄位標題（中文）。

| 分頁名稱 | 用途 |
|---|---|
| `Students` | 學生主檔（含語言證明、延畢、護照、性別、入出境日期等大量欄位） |
| `Positions` | 職缺（實習單位），含地點群組 JSON、7+4 個角色指派欄位 |
| `Matches` | 媒合紀錄（學生↔職缺），含實習場域 |
| `SecondInterviews` | 二面進度 |
| `AdmittedList` | 錄取名單 |
| `ApplicationProgress` | 申辦進度追蹤（11 個階段的進度條） |
| `InTaiwanVisa` | 在台簽證追蹤（兩次入出境日期、換發簽證） |
| `InTaiwanCare` | 在台關懷紀錄 |
| `InternshipDocs` | 實習文件追蹤（9 種文件類型的收件狀態） |
| `HousingRecords` | 住宿安排（依學生分派的住宿紀錄） |
| `Dormitories` | 宿舍管理（宿舍本身的主檔：租期、押金、租金、房仲費、可住人數、當月水電費） |
| `Meetings` | 會議記錄 |
| `ClientFeeSetup` | 客戶費用建檔（月租費率、統編、計費/結算日等） |
| `InternalFeeSetup` | 內部費用建檔（各角色獎金費率） |
| `Bonuses` / `ClientBilling` | **舊版手動輸入表，已停用**——現在「內部獎金計算」
    「客戶請款計算」是即時試算報表，不再讀寫這兩張表，但後端 CRUD 函式還留著，
    刪不刪都不影響現有功能 |
| `Users` | 使用者帳號（bcrypt 前的簡易 salt+hash，見 `hashPassword_`） |
| `RolePermissions` | **動態權限矩陣**（見下方權限系統說明），取代原本寫死在程式碼裡的權限表 |

## 6. 權限系統（重要，改功能前一定要懂）

- 角色清單：`ROLES`（Code.gs）= `['系統管理員','主管','業務人員','服務人員',
  '翻譯人員','國外供應','行政人員','會計人員','宿管人員']`
- 每個「模組」（大致對應一個分頁或一組分頁）都有 `edit` / `view` / `none` 三種等級，
  存在 `RolePermissions` 試算表分頁裡，**不是寫死的**
- `DEFAULT_PERMISSIONS`（Code.gs）是預設值/種子資料，`getRolePermissionsMap_()`
  會在每次讀取時自動幫任何「模組×角色」組合裡缺少的紀錄補上預設值並寫回試算表
  ——這代表**新增角色或新增權限模組時，不需要手動去試算表補資料**，程式會自動處理
- **系統管理員永遠是全模組 `edit`**，這是寫死在 `permFor_()` 裡的安全機制，
  `RolePermissions` 表裡即使有系統管理員的資料也會被忽略，且前端不允許編輯這一列
- 前端對應：`state.roleMatrix`（從 `getAllData` 拿到完整矩陣，僅在對 `users`
  模組有 view 以上權限時才會拿到）、`permissions`（目前登入者自己的權限，每個模組
  一個 key）、`canEdit(moduleKey)` / `canView(moduleKey)`
- 「使用人員」分頁裡的「角色權限說明」表格，對有 `users:edit` 的人是**可以直接點擊
  的按鈕**，點一次循環 `edit → view → none → edit`，即時呼叫
  `updateRolePermission(token, module, role, level)`
- 每個分頁的實際存取權限，是透過 `pageModuleKey(page)`（Index.html）把「頁面 key」
  對應到「權限模組 key」，兩者常常不同名（例如 `clientFeeSetup` 頁面用的是 `bonus`
  權限）。**加新分頁時一定要記得在這裡加映射**，不然預設用頁面自己的名字當權限 key
- 側邊欄分組（`{type:'group', ...}`）的顯示邏輯是**逐一檢查每個子項目自己的權限**，
  不是整組共用一把權限鑰匙——這是因為同一個群組底下的子項目可能屬於不同權限模組
  （例如「資料建檔」群組裡，`bonus` 頁面用的是 `bonus` 權限、`users` 頁面用
  `users` 權限），早期版本曾經整組共用一個 `moduleKey` 導致某些角色看不到群組裡
  他們其實有權限的子項目，後來修正了，**改動側邊欄結構時要小心不要退回舊寫法**

## 8. 各分頁功能重點

### 學生資料
單一學生的完整檔案：基本資料、性別、國籍、語言能力證明（類別/等級/狀態，類別含
華語/多益/雅思）、在學證明、護照號碼、延畢（有/無 + 證明狀態）、夜間實習同意書、
其他文件（可自訂多筆的清單）、第一次/第二次入境離境日期。這些「文件類」欄位
大多跟「實習文件追蹤」**雙向同步**（改任一邊都會同步另一邊，見第 9 節）。
新增學生存檔後會自動在「媒合紀錄」建立一筆「媒合中」的空白紀錄（職缺待補）。

### 職缺媒合（實習單位/媒合紀錄/二面進度/錄取名單）
- 實習單位：職缺主檔，含專案編號、實習場域（地點群組內的子欄位，一個職缺可以有
  多組地點/場域/缺額/狀態）、7+4 個角色指派欄位（開發業務～行政專員 + 會計人員/
  會計助理/宿管人員1/宿管人員2，這些欄位是「內部獎金計算」拿來對照領錢的人）。
  頁面上方有「缺額概況（依產業分類）」統計面板。
- 媒合紀錄：學生↔職缺，狀態 `媒合中/已媒合/取消`。表單用國籍→學校→學生、
  專案編號→實習單位→職務名稱兩組層層篩選下拉選單。選「實習單位」時如果只對應
  一個專案編號會自動帶入。選定職務後「實習場域」只會列出該職缺真正擁有的場域
  （不是全部場域）。狀態改成「已媒合」時若「媒合日期」是空的會自動帶入今天。
  狀態變成「已媒合」時自動在「二面進度」建立一筆「待安排」。
- 二面進度：狀態 `通過` 時自動在「錄取名單」建立一筆「通過二面」。
- 錄取名單：狀態 `確認錄取` 時自動在「實習文件追蹤」建立整組 9 項文件清單、
  在「申辦進度追蹤」建立進度紀錄。**狀態從「確認錄取」改回「通過二面」時，
  會自動刪除該學生在「實習文件追蹤」的整組紀錄**（不可逆）。

### 實習文件追蹤
每位學生固定追蹤 9 種文件：語言能力證明、在學證明、延畢證明、夜間實習同意書、
護照影本、保險證明、其他（申請書、實習合約已於後期移除，不在清單內）。
每個項目可以直接點擊切換已收到/未提供，右上角有 ✎ 開細節編輯、✕ 單項刪除。
文件類型選「延畢證明」時會多出「有延畢/無延畢」的獨立按鈕（不是塞進狀態下拉選單
裡）；選「語言能力證明」時會多出「類別/等級」兩個下拉選單，跟學生資料雙向同步。
全部收齊會自動歸類到「已完成繳交名單」。列表每一列也有「刪除」按鈕可以一次刪除
整組（不是只刪一項）。

### 申辦進度追蹤
11 個階段的進度條（學生錄取 → MOU簽署-學校端用印 → MOU簽署-企業端用印 →
收集學生資料 → 收集企業資料 → 撰寫計劃書 → 企業用印 → 經濟部/交通部審核 →
發函後寄國外 → 辦理簽證 → 住宿安排 → 預約體檢公司 → 入台）。進度到達「入台」時，
自動在「在台簽證追蹤」建立空白紀錄，接著連鎖觸發「在台關懷紀錄」「住宿安排」
各建立一筆空白紀錄。依「專案編號+客戶名稱+實習場域」分組顯示。

### 實習在台追蹤（在台簽證追蹤/在台關懷紀錄）
- 在台簽證追蹤：第一次/第二次入出境日期、兩次換發簽證時間。**分成「第一次入境」
  「第二次入境」兩個分類，但分類依據不是日期欄位本身有沒有填，而是連動別的資料**：
  「第一次入境」連動「實習文件追蹤」的已完成繳交名單（文件全部核准/不適用才會
  出現在這裡）；「第二次入境」連動「第一次離台時間」是否已到達（≤ 今天就自動列入，
  提醒該安排第二次入境）。有「確認離台」勾選框，勾選後該筆從列表消失（資料還在，
  只是不顯示）。新增/編輯時會自動同步學生資料的入出境日期欄位（雙向）。
- 在台關懷紀錄：狀態 良好/待關心/預計離台，同樣有「確認離台」隱藏機制。

### 主管報表
系統管理員/主管專用的整體數據總覽：本月內部獎金/請款試算總額、文件完成率、
學生狀態分佈、住宿狀態分佈、國籍分佈、學生數前 8 大客戶排行。

### 住宿安排
三分類：**未安排**（沒有入住日）/ **住宿中**（有入住日且退宿日未到或沒填）/
**已離宿**（退宿日已過）。已離宿的項目有「已完成」按鈕，按下去該筆就不再顯示於
列表（但資料還在，靠 `completed` 欄位標記）。欄位含宿舍管理員1/2、付款方式
（學生自付/廠商代付）。

### 宿舍管理
獨立於「住宿安排」之外的宿舍主檔清單（管理的是宿舍本身，不是學生↔宿舍的分派），
欄位含宿舍名稱、地點、起租日/退租日、押金金額、房仲費金額、租金金額、可住人數、
當月水費、當月電費、備註。列表可依宿舍名稱/地點搜尋；另有月份選擇器＋「下載本月
清單」按鈕，會依「起租日～退租日」是否涵蓋所選月份篩選出當月仍在租期內的宿舍再
下載 CSV（沿用 `monthRange()`/`dateOverlapDays()` 判斷邏輯，跟簽證追蹤在職天數
計算共用同一套規則）。權限模組是獨立的 `dormManagement`（頁面 key 跟權限 key
同名，`pageModuleKey()` 不需要另外映射）。

### 會計專用（客戶請款計算/學生自付宿舍/學生資料總檔）
- 客戶請款計算：**不是手動輸入表，是每月即時試算報表**。選月份，依「實習單位
  （= 專案編號+客戶）」把所有學生當月在台天數加總，乘以「客戶費用建檔」設定的
  月費率÷當月天數，算出當月應收的辦件費/服務費/宿舍費/宿管費，「客戶費用建檔」
  裡「是否請款住宿費」設為否時宿舍費/宿管費會自動歸零。每一列有「下載請款單」
  按鈕，會即時產生一份 xlsx（用 `SpreadsheetApp.create` 建臨時試算表、匯出
  xlsx、再刪掉暫存檔，不留 Drive 垃圾），含「請款單」（公司抬頭/銀行資訊目前是
  **寫死**在 `COMPANY_INFO`）跟「學生明細」兩個工作表，期別自動算「第 N 期」
  （從該客戶最早學生的入台月份算起）。
- 學生自付宿舍：住宿付款方式為「學生自付」的學生名單。
- 學生資料總檔：依月份彙整所有學生的廠商/專案/證件/當月在職天數/計費起算日/
  請款結算日/是否請款住宿費，可搜尋、可下載。

### 資料建檔（使用人員/客戶費用建檔/內部費用建檔/內部獎金計算）
- 使用人員：帳號密碼管理 + 角色權限說明（可點擊按鈕直接調整權限，見第 6 節）。
- 客戶費用建檔、內部費用建檔：兩張「費率主檔」，一個客戶/專案一列，是「客戶請款
  計算」「內部獎金計算」試算的**資料來源**，不是計算結果本身。
- 內部獎金計算：**跟客戶請款計算一樣是即時試算報表**，不是手動輸入表。依「內部
  費用建檔」的角色費率÷當月天數×學生當月在台天數，以「實習單位」為單位加總算出
  每個角色（開發業務～宿管人員2 共 11 個角色欄位）該月的獎金金額，欄位顯示指派
  人員姓名+金額（姓名抓自「實習單位」表單裡各角色欄位）。頁面下方另有「依人員
  加總」區塊，把同一人在不同客戶底下的獎金合併成一筆總額。

## 10. 前端程式碼慣例（維護時建議遵守，避免風格不一致）

- 每個「列表型」分頁大致是同一套骨架：`render<Page>()` 產生 HTML 字串（含
  搜尋框、分類/分組、表格或卡片）→ `<Page>FormModal(existing)` 產生新增/編輯
  表單的 HTML → `attachPageEvents()` 裡對應的區塊用 `document.getElementById`
  / `querySelectorAll` 綁事件、呼叫 `gsRun` 打後端、成功後 `await loadAll()`
  重新整批抓資料再整頁重繪（**沒有局部更新機制**，任何一次寫入都會重新拉全部
  資料）
- CSV 下載/匯入共用 `exportEntityCSV()` / `parseImportRows()` /
  `handleImportGenericFile()` / `wireGenericImportExport()` / 
  `importExportButtonsHTML()` 這組泛用函式，新增一個可下載/匯入的分頁時
  應該重用這組，不要重新寫一遍
- 依「專案編號+客戶名稱（+實習場域）」分組是好幾個分頁共用的模式，共用函式是
  `groupByProjectCompany()` / `studentProjectCompanyKey()` /
  `matchPositionLabel()` / `positionCompanyLabel()`
- 「國籍→學校→學生」層層篩選下拉選單的共用函式是 `wireStudentSearchSelect()`
  （較新、通用版本）；媒合紀錄表單自己有一套幾乎一樣但獨立維護的
  `rebuildMatchStudentOptions()`／`wireMatchFilters()`，**這是歷史包袱**，
  理論上可以合併成同一套，但目前沒有動它以避免破壞現有邏輯
- 搜尋框統一用 `wireSearchInput(inputId, setValue)`，會處理游標位置保留（避免
  每次輸入都跳到欄位最後）
- 月份選擇器（`<input type="month">`）搭配的即時試算報表模式：
  `<Page>CalcMonth` 全域變數存目前選的月份、`currentMonthStr()` 給預設值、
  `monthRange()` / `dateOverlapDays()` / `studentDaysInTaiwanForMonth()`
  是核心的「某學生某月在台天數」計算函式，新增任何跟「當月在職天數」有關的功能
  都應該重用這幾個函式，不要重新寫日期運算
- 條件顯示欄位（例如文件類型選到「延畢證明」才出現的欄位）的寫法是：表單裡先用
  `style="display:none;"` 藏起來，另外寫一個 `wire...Toggle()` 函式監聽觸發
  欄位的 `change` 事件切換 `style.display`
- 顏色標籤用共用的 `tag(text, map)` 函式 + 各分頁自己的 `xxx_TAG` 物件
  （例如 `STUDENT_TAG`、`CARE_TAG`、`POSITION_TAG`）
- **所有新增分頁都要同時記得三件事**：(1) `NAV_STRUCTURE` 加項目 (2) `render()`
  裡加 `if(currentPage==='xxx') root.innerHTML = renderXxx();` 這行**非常容易漏掉**
  （曾經發生過漏加導致頁面整個空白的事故）(3) 如果權限 key 跟頁面 key 不同名，
  要去 `pageModuleKey()` 加映射

## 11. 已知限制 / 技術債

- `Bonuses`、`ClientBilling` 兩張表已經沒有任何 UI 在讀寫，但後端 CRUD 函式
  （`addBonus`/`updateBonus`/`deleteBonus`/`addClientBilling`/...）還留著沒刪，
  純粹是懶得清，不影響功能
- 沒有樂觀鎖 / 並發衝突偵測：兩人同時編輯同一筆資料，後存的會直接覆蓋先存的，
  不會跳警告
- 請款單 Excel 產生功能（`generateClientInvoice`）裡，公司抬頭/地址/銀行帳戶
  是寫死在 `COMPANY_INFO` 常數裡，沒有做成可在介面編輯；也沒有放公司浮水印/
  印章圖片；沒有「期別」以外的手動調整欄位（使用者曾詢問要不要加「其他加項/
  其他扣項/代收代付」的手動調整項目，**這個功能最後沒有真的做完**，只有討論
  到欄位需求就被後續訊息蓋過去了，是一個明確待補項目）
- 媒合紀錄表單的學生/職缺篩選邏輯跟其他分頁用的是兩套不同、功能重疊的程式碼
  （見第 10 節倒數第三點），未來可以考慮合併重構
- 「主管報表」「學生資料總檔」等頁面沒有自動化測試，任何修改都要手動在瀏覽器
  裡逐一點過一遍確認
- 目前沒有版本控制（沒有 git repo），這份 `Code.gs`/`Index.html` 就是唯一的
  真實來源，**強烈建議 Claude Code 接手後第一件事是把這兩個檔案放進 git 做
  版本控制**，避免之後改壞了無法回退
